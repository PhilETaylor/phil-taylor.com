## Design Context

### Users
Mixed audience of potential clients (seeking PHP/SaaS/DevOps expertise or site fixes) and technical peers (developers, open source community, industry contacts). Visitors arrive with a specific intent: either evaluating Phil as a hire/collaborator, or looking up contact and project info. The site needs to serve both without alienating either group.

### Brand Personality
**Competent, direct, technical.** A serious professional who lets expertise and track record speak for itself. No flash, no hype. The design should communicate depth of experience through restraint and precision, not through visual noise.

### Aesthetic Direction
- **Reference:** GitHub profile page. The current Primer-based design is the canonical reference - lean into it, not away from it.
- **Color system:** GitHub Primer palette with full light/dark mode via `prefers-color-scheme`. Blues for interactive elements, neutral grays for structure, green for success states, gold for star ratings.
- **Typography:** System font stack (Apple system, Segoe UI, Noto Sans) for body, monospace (SF Mono, Menlo, Consolas) for technical elements like SSH keys and GPG fingerprints.
- **Layout:** Two-column GitHub profile: fixed-width sidebar (296px on desktop, collapsed on mobile) with avatar, contact, social links, skill pills, and client icons. Flexible main column with content sections.
- **Components:** Bordered cards with subtle hover-lift (translate-y + border color + shadow), pill badges for skills, testimonial cards with star ratings, project grid (2-col on desktop), tooltip popovers on client icons.
- **Interactions:** Minimal and purposeful. Hover states use small translate-y shifts, border color changes, and soft shadows. Cursor-blink animation for terminal personality. No gratuitous animation.
- **Anti-references:** Marketing-heavy landing pages, portfolio sites with hero banners, anything with gradients or illustration-heavy aesthetics. This is not a sales page - it's a profile.

### Design Principles
1. **Let the content prove competence.** The design should never try harder than the work itself. Testimonials, project lists, and credentials do the talking - the design just makes them easy to scan.
2. **GitHub is the vernacular.** Developers understand GitHub's visual language instinctively. Using Primer conventions (card borders, muted text hierarchy, icon + label patterns) means zero learning curve for the technical audience.
3. **Restraint is the brand.** Every element earns its place. No decorative flourishes, no empty space fillers, no visual complexity that doesn't serve comprehension. White space is structural, not aesthetic.
4. **Dark mode is a first-class citizen.** Both themes must feel intentional, not like one is an afterthought. Primer's dark palette handles this naturally.
5. **Trust through consistency.** Uniform spacing, predictable interaction patterns, and a tight type scale (2xl/base/sm/xs) signal attention to detail - the same quality a client expects from the code.
